# MuseGarden（音迹花园）项目过程与完整总结

> 状态快照：截至 2026-11-06，供课程材料整理和撰写报告时参考。项目由一人独立开发。具体测试记录以执行时的日志和环境为准；本文不是最终提交的课程报告。

## 一、项目是什么

MuseGarden 是一个结合文字记忆、AI 音乐和像素花园的本地应用。用户在花园中移动并选择空地，写下自己的情绪或经历；系统据此生成音乐与花朵，把它们作为一段可回访的记忆保存在花园里。用户之后可以查看原文、播放音乐、阅读音乐解读，或提出修改要求并切换音乐版本。

项目的出发点是降低音乐创作门槛，让不具备专业作曲经验的人也能尝试通过文字表达情绪；花园和花朵则为记忆提供一个可探索的视觉空间。项目并非直接模仿某部特定作品，而是由作者对 AI 音乐和情绪花园的兴趣结合而来。

## 二、项目过程

1. **选题与立项**：比较 AI 音乐与情绪花园等方向，确定将两者结合；整理项目目标、目标用户、核心功能、思维导图和 NABCD 分析。个人项目按真实情况记录，不虚构团队会议。
2. **需求与规划**：围绕花园探索、文字创作、花朵记忆、音乐播放和修改等功能整理需求，划分项目范围、技术约束和工作计划。
3. **核心模块实现**：分别实现文字情绪理解与音乐蓝图、音乐生成、花朵生成、应用编排和本地数据保存，再通过服务接口连接。
4. **花园交互实现**：使用 React、TypeScript 和 PixiJS 建立可移动的花园世界、种植区域、摄像机和地图，逐步接入创建、回访、播放、音乐修改与版本选择。
5. **功能完善**：增加花朵移除与种植位释放、音乐辅助解读和修改建议；保留原始文字、音乐与版本的本地归档。
6. **测试与反馈**：整理自动化测试、人工操作截图及用户体验反馈。根据初次使用不易理解操作的反馈，增加首次引导与可再次打开的“新手指引”。
7. **展示与迭代**：整理 Gitee Wiki、项目展示页和课程资料；优化花园地形、树木与建筑、碰撞、花朵详情、记忆输入和地图弹窗，并归档新版截图。新版图片不替代历史测试证据。

具体时间、每次提交与更细的开发步骤应查阅各模块日志及 Git 历史；以上是阶段归纳，不表示每一阶段完全按线性顺序发生。

## 三、当前主要功能

- **探索与地图**：使用 WASD 或方向键移动，按 M 查看地图、当前位置、种植区域、道路和水域；道路、桥梁、河流、建筑与树木构成花园环境。
- **种下记忆**：靠近可种植空地按 E 输入文字，系统调用本地 AI 和音乐服务生成作品并在花园中种下花朵。
- **回顾与播放**：靠近花朵按 E 查看对应文字、花朵和音乐，并播放当前或已有版本。
- **音乐修改**：用户可输入修改要求或参考 AI 建议，生成新版本；已有版本可保留、选择和播放。
- **音乐解读**：展示辅助聆听信息，包括部分音频测量和编配设置的说明；它是辅助解读，不能视为对音乐内容完全准确的判断。
- **移除花朵**：靠近花朵按 Delete 或 Backspace 移除花园中的种植记录，释放位置；原始记忆与音乐版本仍保存在本地归档。
- **使用引导**：首次进入显示基础操作说明，之后可以从界面再次打开。

## 四、技术结构与数据流

```text
文字记忆 → AI Engine：情绪理解与音乐蓝图
                 ├→ Music Engine / ACE-Step：生成音频
                 └→ Flower Engine：生成花朵表现
                         ↓
应用服务与后端：保存创作、音频、花朵和种植关联
                         ↓
React + TypeScript + PixiJS：花园交互、详情与播放
```

主要目录：`ai_engine/`（文字理解与蓝图）、`music_engine/`（音乐生成）、`flower_engine/`（花朵）、`application/`（业务编排）、`backend/`（接口）、`frontend/`（界面）、`database/`（本地数据）、`docs/`（设计与课程资料）、`test/`（测试）。本地启动还需要 Ollama、ACE-Step 及相应模型；启动与依赖细节以 [前端运行说明](../../frontend/README.md) 为准。

## 七、当前限制与后续工作

1. 项目目前是本地单用户应用，依赖本机服务、模型和环境；不具备完整的多用户、云同步或公开在线 AI 生成服务。
2. 新创作尚未接入对历史记忆的语义检索；版本数据仍主要保存在当前本地创作层，多个 JSON 文件之间没有跨文件事务。
3. 视觉和碰撞做过多轮调整，复杂树群、建筑边缘及完整创作流程仍应在当前版本人工复测；不能仅凭截图或旧测试日志推断全部场景通过。
4. 课程最终报告尚待按老师的模板完成，封面和个人体会按真实信息填写。个人项目的会议照片、任务数量和原型形式等要求应向老师确认。
5. 提交前重新核对 Wiki 图片、展示页、运行方式、测试结果以及老师最终要求；用户反馈、照片和过程记录不虚构。
