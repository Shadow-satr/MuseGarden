# MuseGarden（音迹花园）设计与实现说明

> 项目形式：个人独立开发的软件工程课程项目  
> 文档版本：V1.0  
> 内容依据：当前可运行源代码与本地测试结果

## 1. 设计目标

MuseGarden 的设计围绕一条完整业务链展开：用户将文字记忆输入花园，系统理解文字情绪并生成音乐，再根据同一份音乐蓝图生成花朵，将花朵种植到像素风地图中。用户之后可以在花园里查看记忆、播放和修改音乐、切换历史版本，或删除花朵以释放种植位置。

设计重点是让“文字—音乐—花朵—花园”四类对象保持关联，同时将界面、业务编排、AI 能力、音乐生成和花朵生成分开实现。

## 2. 技术选型

| 层次 | 当前技术 | 作用 |
| --- | --- | --- |
| 前端 | React、TypeScript、PixiJS、Vite | 页面状态、像素地图渲染、角色移动和交互弹窗 |
| 本地接口 | Python `ThreadingHTTPServer`、Pydantic | 提供 JSON 接口、请求校验和音频文件响应 |
| AI 音乐蓝图 | Ollama 本地模型 | 从文字分析情绪，生成或编辑音乐 Blueprint |
| 音乐生成 | ACE-Step | 根据 Blueprint 生成 WAV 音频 |
| 音乐解读 | Music Companion 模块 | 分析当前音频，生成音乐解读和修改建议 |
| 花朵与花园 | Flower Engine | 生成花朵外观规格、维护花园和种植记录 |
| 数据保存 | 本地 JSON 文件与 WAV 文件 | 保存记忆、创作、音频、花朵、种植关系和版本信息 |

## 4. 前端设计

### 4.1 花园世界

`GardenWorldView` 负责挂载 PixiJS 花园世界；`GardenWorld` 管理地图、角色、相机、可交互对象和花园刷新。地图由 `TerrainMap` 数据驱动，水域、建筑等不可通行区域参与碰撞判断。用户可使用 `WASD` 或方向键移动角色。

前端将可交互对象区分为两种：

- 空地：角色进入后按 `E` 打开“创建记忆”弹窗；
- 已种花朵：角色靠近后按 `E` 打开花朵详情，按 `Delete` 删除花朵。

按 `M` 可打开小地图，`/map-overview` 提供花园总览页面。

### 4.2 界面状态与容错

`App.tsx` 统一管理创建、详情、音乐修改、版本切换、删除和地图状态。对可能耗时的请求使用 `AbortController` 管理取消，避免用户关闭弹窗后旧请求覆盖新界面状态。

创建记忆包含 `idle`、`loading`、`syncing`、`success`、`error` 等状态；当“后台已创建成功但前端刷新失败”时，界面会提示用户回到花园检查，而不会直接引导重复提交。

## 5. 核心业务流程

### 5.1 创建记忆、生成音乐与种植花朵

```text
用户在空地按 E，输入文字
  → 前端 POST /api/creations
  → CreationService 校验花园与种植位置
  → AI Engine：情绪理解 + Music Blueprint
  → Music Engine：ACE-Step 生成 WAV，保存 AudioArtifact
  → Flower Engine：按初始 Blueprint 生成 FlowerArtifact
  → GardenService：创建 PlantingRecord
  → 保存 MusicMemory、FinalCreation、DemoCreationRecord
  → 返回文字、音乐、花朵和种植信息
  → 前端刷新花园，在目标位置显示花朵
```

种植时会检查位置冲突。小花占用 `1 × 1` 格；较大花朵占用 `3 × 3` 格。当地图空间不足时，当前实现可按规则降级花朵规格；中心位置无效则拒绝种植。

### 5.2 查看、解读与修改音乐

打开花朵详情后，前端按种植记录和花朵资产读取关联创作。用户可以播放当前音频，查看版本列表并选择不同版本。

音乐解读先读取已保存结果；不存在或分析版本变化时，后端调用 Music Companion 分析音频并保存结果。修改音乐时，系统根据原始文字、当前 Blueprint 和用户修改要求生成新的 Blueprint，再由 ACE-Step 生成新的音频版本。旧版本不会被覆盖。

### 5.3 删除花朵

前端对 `DELETE /api/gardens/{garden_id}/plantings/{planting_id}` 发起请求。应用层删除花园中的种植记录，并将对应创作记录中的花朵和种植引用置空。因此，土地会恢复可种植状态；文字记忆、音乐和版本历史仍保留在本地。

## 6. 数据设计

| 数据对象 | 主要内容 | 作用 |
| --- | --- | --- |
| `MusicMemory` | 原始文字、情绪、音乐 Blueprint | 保存用户的音乐记忆基础信息 |
| `AudioArtifact` | WAV 音频、版本关联和生成时间 | 保存可播放音乐文件的元信息 |
| `FinalCreation` | 草稿、Blueprint、音频、记忆的关联 | 固化一次已完成创作 |
| `FlowerArtifact` | 花种、像素渲染规格、变体信息 | 决定花朵的显示外观 |
| `PlantingRecord` | 花朵 ID、花园 ID、坐标、占用格子 | 维护花朵在花园中的位置 |
| `DemoCreationRecord` | 当前播放版本、版本列表、花朵和种植引用 | 面向当前网页的创作聚合记录 |

所有记录使用 UUID 作为关联标识。音频二进制内容以 WAV 文件保存，其他结构化信息以 JSON 保存。接口传递花朵随机种子时使用十进制字符串，以避免 JavaScript 对 63 位整数的精度损失。

## 7. 主要接口

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| GET | `/api/garden-preview` | 获取花园和种植花朵的渲染数据 |
| POST | `/api/creations` | 创建文字记忆、音乐、花朵和种植记录 |
| GET | `/api/creations` | 获取当前花园的创作列表 |
| GET | `/api/audio/{audio_id}` | 读取并播放 WAV 音频 |
| POST | `/api/creations/{creation_id}/music` | 根据修改要求生成新的音乐版本 |
| POST | `/api/creations/{creation_id}/music-selection` | 切换当前播放版本 |
| POST | `/api/creations/{creation_id}/music-version-name` | 重命名音乐版本 |
| POST / GET | `/api/music-companion/{audio_id}` | 生成或读取音乐解读 |
| POST | `/api/music-companion/{audio_id}/suggestions` | 获取 AI 修改建议 |
| DELETE | `/api/gardens/{garden_id}/plantings/{planting_id}` | 删除花朵和种植记录 |

## 8. 当前边界与后续优化

- 当前为单用户本地应用，不包含账户、多人协作和云端同步；
- 当前使用多个 JSON 文件保存数据，尚未实现跨文件事务、任务队列和并发控制；
- 当前创作会保存记忆，但创建新音乐时明确使用 `use_memory=False`，因此尚未将历史记忆检索接入正式创作流程；
- 版本历史目前由网页使用的 `DemoCreationRecord` 管理，尚未与 AI Engine 的正式草稿生命周期完全统一；
- AI 音乐生成与解读依赖本机 Ollama、ACE-Step 和模型环境，速度与可用性受设备状态影响。

这些边界不影响当前课程项目的核心闭环，但为后续扩展数据库、云端同步和更完整的 AI 记忆功能保留了方向。
