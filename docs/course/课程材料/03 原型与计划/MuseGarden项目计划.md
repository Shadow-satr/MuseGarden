# MuseGarden（音迹花园）项目计划

> 项目形式：个人独立开发的软件工程课程项目  
> 计划版本：V1.0  
> 项目状态：迭代开发中

## 1. 计划目标

本计划用于安排 MuseGarden 的课程项目工作，确保项目形成“需求分析—原型与计划—设计实现—测试验证—文档交付”的完整过程。项目采用个人独立开发方式，围绕“文字记忆生成音乐，并以花朵种植到像素花园中”的核心闭环推进。

## 2. 开发策略

项目采用小步迭代方式：先完成可进入、可移动的花园基础场景，再逐步补充创建记忆、生成音乐、种植花朵、查看详情、修改音乐和管理版本等功能。每完成一个功能闭环，即通过本地运行和测试确认，再继续扩展。

## 5. 里程碑与验收标准

| 里程碑 | 验收内容 | 验收方式 |
| --- | --- | --- |
| M1：立项确认 | 项目目标、用户、选题过程和 NABCD 完整 | 检查立项记录与思维导图 |
| M2：需求确认 | 需求能够覆盖实际已有功能，不虚构未实现内容 | 对照源代码、界面和需求分析文档 |
| M3：原型确认 | 四类主要界面均有实际运行截图和交互说明 | 检查 P1—P4 原型截图 |
| M4：核心闭环确认 | 能创建文字记忆、生成音乐和花朵、种植并查看 | 本地演示完整创建流程 |
| M5：音乐迭代确认 | 能播放、查看解读、生成新版本并切换版本 | 本地演示花朵详情流程 |
| M6：花园整理确认 | 能删除花朵并恢复种植位置 | 本地演示 Delete 删除操作 |
| M7：课程交付确认 | 文档、截图、测试材料和使用说明齐全 | 对照最终提交清单 |

## 6. 关键风险与应对措施

| 风险 | 可能影响 | 应对措施 |
| --- | --- | --- |
| 本地 AI 或 ACE-Step 生成耗时较长 | 用户等待时间不稳定 | 界面显示生成中状态；演示前提前检查模型和服务状态 |
| AI 服务不可用或返回异常 | 音乐生成、解读或建议功能失败 | 提供错误提示和重试入口；AI 建议保留预设兜底内容 |
| 种植位置冲突 | 花朵可能与地形或其他花朵重叠 | 创建前校验中心位置；空间不足时按实现规则调整花朵规格 |
| 本地数据关联不一致 | 花朵、种植记录、音乐版本无法正确对应 | 通过接口测试和手工回归，重点检查创建、修改、删除后的数据 |
| 课程材料与实际功能不一致 | 影响项目可信度 | 所有文档以当前可运行版本为准，及时更新截图和说明 |

## 7. 当前验收重点

下一阶段优先完成测试与使用说明，并针对以下核心链路收集证据：

1. 进入花园、移动角色、查看地图；
2. 在空地创建文字记忆，生成音乐和花朵；
3. 查看花朵详情，播放音乐、查看音乐解读和版本；
4. 通过 AI 建议或自定义文字修改音乐；
5. 删除花朵后确认土地可再次使用；
6. 重启项目后确认本地数据仍可恢复。
